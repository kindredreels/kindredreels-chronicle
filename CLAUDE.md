# Kindred Reels Chronicle

## What This Is

An analytics and storytelling tool for the Kindred Reels project — a collaborative platform for creating cinematic video memories from family photos and voice recordings. Kindred Reels is a 250K+ line production web app built through AI-assisted development (Claude Code): Dimitri never writes code directly. His daughter Sadie, a software engineer, joined in December 2025 and wrote the backend's first tests, the first browser tests, and led the first security audit. This repo tells that story both quantitatively and qualitatively, and calls out Sadie's work wherever it appears (`src/utils/people.ts`).

This repo was bootstrapped from the `code-chronicle/` tool that previously lived inside the Kindred Reels codebase. It's being expanded into a full React application with multiple views.

## What Kindred Reels Is (for context)

Kindred Reels (kindredreels.com) lets families create cinematic tribute videos by:
- Uploading photos with AI-powered curation (Gemini for analysis, Rekognition for face detection)
- Inviting family members to record voice memories for photos
- Generating professional videos with Ken Burns effects, beat-synced music, and themed slides

Tech stack: React/TypeScript frontend, Node.js/Lambda backend, Python video rendering on Google Cloud Run Jobs (EC2 as a fallback), a Cloud Run video-clip analyzer, DynamoDB, S3 and GCS, Gemini for analysis.

## Repo Structure

- `scripts/` — Data collection and processing scripts
- `scripts/enrichments/` — hand-checked summaries for PRs after #185, one JSON file per update, merged by `generate-entries.js`
- `data/` — Generated data files (snapshots, PR entries, phases) plus `story.json`, the hand-written lede and the three acts that group the chapters
- `data/phases.json` — the chapters (`phases` in code), each with a narrative and, where Sadie contributed, a `sadieNote`
- `src/` — React application (being built)
- `dashboard/` — Legacy vanilla JS dashboard (to be replaced by React app, then removed)
- `output/` — Generated documents

## Key Context

- The Kindred Reels repo is private on GitHub. `extract-prs.js` uses `gh api` (REST) with explicit page numbers; `gh pr list` and `--paginate` do not work in Claude Code cloud sessions (GraphQL and numeric-id links are blocked).
- `collect-stats.js` checks out every day's commit, so point `KINDRED_REELS_REPO_PATH` at a separate full-history clone, not a working copy you are using.
- The Kindred Reels repo may be available locally — check environment or ask.
- Code stats collection script needs a path to the Kindred Reels repo to count lines.
- PR commit messages are extremely detailed (generated by Claude Code) and are often richer than PR descriptions.

## Updating the story

1. `npm run update` collects stats, extracts PRs and orphan commits, and rebuilds the data.
2. Write summaries for the new PRs into a new file in `scripts/enrichments/` (same fields as the existing entries), then `npm run generate-entries && npm run generate-orphans && npm run build-data`.
3. Revisit `data/phases.json` and `data/story.json`: re-cut chapters when the story has moved, not just append. Every entry must sit in exactly one chapter; `build-data.js` checks every chapter sits in one act.
